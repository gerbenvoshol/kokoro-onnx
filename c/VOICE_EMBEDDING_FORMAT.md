# Voice Embedding Format

## Overview

This document explains the voice embedding format used in kokoro-onnx and how it differs between the Python and C implementations.

## Python Implementation

In the Python version, voice embeddings are stored as 2D NumPy arrays:

```python
# Shape: [max_length, embedding_dim]
# Example: [510, 256]
voices = np.load('voices.npz')
voice_embedding = voices['af_sarah']  # Shape: [510, 256]
```

During inference, the embedding is indexed by the token count:

```python
tokens = tokenize(phonemes)
voice = voice_embedding[len(tokens)]  # Select row based on token count
# Result shape: [256]
```

This is passed to the ONNX model with shape `[1, 256]`.

## C Implementation

### Voice File Conversion

The `scripts/convert_voices.py` script converts the Python `.npz` format to a C-compatible binary format. When it encounters 2D embeddings, it **flattens** them:

```python
# Original: [510, 256]
# Flattened: [130560]  (510 * 256 = 130560)
embedding = embedding.flatten()
```

### Binary Format

```
File structure:
- uint32_t num_voices        (e.g., 54)
- uint32_t embedding_size    (e.g., 130560 for 2D, 256 for 1D)
- For each voice:
  - uint32_t name_length
  - char[] name
  - float32[] embedding       (flattened if 2D)
```

### C Code Handling

The C code detects whether embeddings are 1D or 2D (flattened) based on size:

```c
if (embedding_size == 256) {
    // 1D embedding: use directly
    is_2d_embedding = 0;
    voice_dim = 256;
} else if (embedding_size == 130560) {
    // 2D embedding (flattened): needs indexing
    is_2d_embedding = 1;
    voice_dim = 256;
}
```

During inference, if the embedding is 2D, it indexes into the flattened array:

```c
if (is_2d_embedding) {
    // Calculate offset: phoneme_count * voice_dim
    int phoneme_count = num_tokens - 2;  // Exclude padding
    size_t offset = phoneme_count * voice_dim;
    style = voice_embedding + offset;
} else {
    // 1D: use directly
    style = voice_embedding;
}
```

This produces the same result as the Python code: a pointer to a `[256]` vector, which is passed to ONNX with shape `[1, 256]`.

## Example

For a text with 10 phonemes (12 tokens including padding):

**Python:**
```python
tokens = [0, tok1, tok2, ..., tok10, 0]  # 12 tokens
voice = voice_embedding[10]  # Row 10, shape [256]
```

**C:**
```c
// phoneme_count = 10
// offset = 10 * 256 = 2560
// style points to embedding[2560:2816]
style = voice_embedding + 2560;
// style_shape = [1, 256]
```

Both produce identical results: a 256-dimensional vector representing the voice style for sequences of length 10.

## Why This Matters

The voice embedding varies with sequence length because the model learns different style representations for different sequence lengths. This is a design choice in the Kokoro model architecture that allows it to adapt the voice characteristics based on the input length.

## Compatibility

The C implementation now correctly handles both:
- **1D embeddings**: Size 256, used directly
- **2D embeddings (flattened)**: Size 130560 (or any multiple of 256), indexed by token count

This ensures compatibility with all voice file formats generated by the conversion script.
